# Day 33–34: 100B training ka storage

100B parameters. BF16 weights ≈ `100e9 × 2 = 200 GB`. Adam states ≈ `100e9 × 16 bytes ≈ 1.6 TB` per full replica, ZeRO se pehle. ZeRO-3 yeh N GPUs pe bikher deta hai. Checkpoint ka **total** size phir bhi usi order ka hai, kyunki saare shards milakar wahi state hain.

Do flows ko ek disk pe mat daalo.

| Flow | Pattern | Storage |
|---|---|---|
| Training data | Sequential, dobara read, bahut readers | Tar shards + local cache. Source S3 ho sakta hai. |
| Checkpoint | Burst write, sab ranks, har K minute | Parallel FS pe likho, phir async S3 pe cold copy. |

**Read path cache karo. Write path parallel FS pe burst karo. S3 cold copy hai.**

Assignment 2.1: concurrency badha kar TTFT aur ITL naapo. Prefill queue lambi ho to TTFT badhti hai. Decode memory-bound hai, isliye ITL tab tak theek rehti hai jab tak KV cache bandwidth na kha jaaye. Code baad mein `02-inference-engines/ttft-itl-benchmark/` mein hoga.

**Rule:** data aur checkpoint ka pattern alag hai. Ek hi NFS dono ko nahi sambhalta.
