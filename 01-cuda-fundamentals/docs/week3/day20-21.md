# Day 20–21: Toy pipeline timeline, aur Assignment 1.3

4 layers, 4 GPUs, 4 microbatches. Paper pe time left se right hai. `F1` matlab microbatch 1 ka forward.

```text
time →
GPU0: F1 F2 F3 F4 B1 B2 B3 B4
GPU1:    F1 F2 F3 F4 B1 B2 B3 B4
GPU2:       F1 F2 F3 F4 B1 ...
GPU3:          F1 F2 F3 F4 B1 ...
```

Shuru aur end ke khali triangles **bubble** hain. GPU3 tab tak wait karta hai jab tak GPU0 ka pehla forward us tak na pahunche. Beech mein, jab pipeline bhar jaaye, zyada tar slots kaam kar rahe hote hain.

Assignment 1.3: Week 2 wala tiled matmul `ncu` se dekho. Teen numbers:

- **Occupancy.** SM pe kitne warps active reh sakte hain, registers aur shared memory ke hisaab se. 100% zaroori nahi. Bahut kam occupancy aur memory wait ek saath hon to GPU ko doosra warp switch karne ko nahi milta. Day 2 wala intezaar chhup nahi pata.
- **Stall reason.** `long scoreboard` aksar matlab "memory ka intezaar". `barrier` matlab sync. `not selected` matlab koi aur warp chal raha tha, yeh wait kar raha tha.
- **Memory throughput.** Achieved vs peak. Week 1 ka T4 vector-add peak ka lagbhag 22% tha. Tiled GEMM is number ko upar le jaane ki koshish hai, kyunki tile SRAM mein reuse hota hai.

**Rule:** timeline pe bubble dikhta hai. `ncu` pe memory stall aur throughput dikhte hain. "GPU busy" akela jawab nahi hai.
