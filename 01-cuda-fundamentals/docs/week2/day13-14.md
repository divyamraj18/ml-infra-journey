# Day 13–14: 8 GPUs, 2 nodes, ek AllReduce

Weekend ka kaam yeh diagram hai. 8 GPUs, 2 nodes, iska matlab **4 GPUs per node**. Yeh ek 8-GPU DGX nahi hai. Do aadhe boxes hain, beech mein fabric hai.

Socho do campuses. Har campus mein 4 factories, andar NVSwitch. Campus ke bahar sirf highway (NIC) hai.

## Physical topology

```text
Node 0                                      Node 1
GPU0   GPU1   GPU2   GPU3                   GPU4   GPU5   GPU6   GPU7
  \     |      |     /                        \     |      |     /
        NVSwitch                                    NVSwitch
   |     |      |     |                        |     |      |     |
  NIC0  NIC1   NIC2  NIC3                     NIC4  NIC5   NIC6  NIC7
   |     |      |     |                        |     |      |     |
 rail0  rail1  rail2  rail3                   rail0  rail1  rail2  rail3
   \     |      |     /                        \     |      |     /
        leaf / spine (InfiniBand ya RoCE)
```

Node ke andar har pair NVSwitch pe hai. H100 hon to Day 8 wala ~900 GB/s. Node ke bahar sirf NIC.

**Rail** same index ke NICs ko jodti hai. Node 0 ka GPU0 aur Node 1 ka GPU4 dono rail 0 pe hain. Fabric rail-optimized ho to unke beech ka IB hop spine cross kiye bina ho sakta hai.

`nvidia-smi topo -m` node ke andar `NV` aur `PIX` dikhayega. Doosre node ka GPU us matrix mein hota hi nahi. Woh door hai, `NET/IB` se.

## Ek naive ring: ek hi highway

Ranks `0-1-2-3-4-5-6-7-0`.

```text
GPU0 -> GPU1 -> GPU2 -> GPU3 -> GPU4 -> GPU5 -> GPU6 -> GPU7 -> GPU0
         NVLink hops          IB hop          NVLink hops         IB hop
```

Sirf do hops inter-node hain: `3 → 4` aur `7 → 0`. NCCL ring aise bichha de to dono ek hi rail use karte hain. Rail 1, 2, aur 3 khali. `4 × 400 Gb/s` mein se 400 Gb/s kaam kar raha hai.

Andar ke hops saste hain, kyunki woh NVLink hain. Bottleneck woh do InfiniBand hops hain.

Ring AllReduce ka jawab phir bhi sahi aayega. Bus bandwidth ek rail ki hogi, chaar ki nahi. Yeh wahi bug hai jisme loss sahi rehta hai aur step slow hota hai.

## NCCL actually kya banana chahta hai

Topology dikhe to ek ring nahi, **chaar rings**, ek per rail. Har step pe chaaron NICs bytes le jaate hain.

Do nodes pe natural pattern hierarchical hai:

```text
1. Intra-node, NVLink
   Node 0: GPU0..GPU3  apne buffer ka ReduceScatter
   Node 1: GPU4..GPU7  apne buffer ka ReduceScatter
   Ab har GPU ke paas buffer ka 1/4 tukda hai, node ke andar sum ho chuka.

2. Inter-node, ek rail per shard
   GPU0 <-IB rail0-> GPU4     in tukdon ka sum
   GPU1 <-IB rail1-> GPU5
   GPU2 <-IB rail2-> GPU6
   GPU3 <-IB rail3-> GPU7
   Chaaron rails ek saath.

3. Intra-node, NVLink
   AllGather, taaki node ka har GPU poora AllReduce result rakh le.
```

Step 2 chhota hai kyunki shard `S/4` hai, aur chaar rails parallel hain. Naive ring poora traffic ek IB hop ki line mein khada kar deta tha.

Buffer `S = 14 GB` ho (7B, BF16 gradients). Step 2 pe har rail ek direction mein `S/4 = 3.5 GB` dekhti hai, phir result wapas aata hai. Exact byte count algorithm pe depend karta hai. Order yeh hai: inter-node bytes `S / number_of_nodes` ke aas-paas, rails pe bate hue. Intra-node bytes NVLink pe hain, 900 GB/s, isliye woh IB se pehle khatam ho jaate hain.

## Ek chunk ko haath se ghumao

8 chunks, `c0` se `c7`. Sirf `c0` dekho, naive ring pe, ReduceScatter phase mein.

```text
start:  GPU0 holds c0 (sirf rank 0 ka partial)
step 1: GPU0 sends c0 to GPU1.  GPU1 adds its own c0.
        hop = NVLink
step 2: GPU1 sends c0 to GPU2.  GPU2 adds.
        hop = NVLink
step 3: GPU2 sends c0 to GPU3.  GPU3 adds.
        hop = NVLink
step 4: GPU3 sends c0 to GPU4.  GPU4 adds.
        hop = InfiniBand, NIC3 ki rail
```

Chaar steps ke baad `c0` abhi poora summed nahi hai. Rank 4, 5, 6, aur 7 ka hissa abhi jodna baaki hai.

Yeh walk yeh dikhane ke liye hai: **chunk tab IB pe chadhta hai jab ring node ki boundary cross karti hai.** Usse pehle woh NVLink pe rehta hai.

Hierarchical version mein `c0` node 0 ke andar NVLink pe sum hota hai, phir **ek baar** rail 0 pe GPU4 ko jaata hai. Wahan node 1 ka pehle se reduced shard add hota hai. GPU1 aur GPU2 us chunk ko IB tak le jaane ke liye relay nahi bante.

## AllReduce ke dauran kaun wait karta hai

Compute tab overlap hota hai jab framework gradient ko **buckets** mein kaat de, aur bucket ready hote hi AllReduce shuru kar de.

Poora backward khatam karke ek bada AllReduce chalana = GPU network ka intezaar kare.

NCCL async hai. Collective CUDA stream pe schedule hota hai. Day 4 wali stream yahan kaam aati hai: ek stream pe GEMM, doosri pe NCCL. Hardware dono ko overlap kar sakti hai.

Overlap ke baad bhi step time mein `ncclAllReduce` sabse lamba ho, to Day 12 pe wapas jao: INFO log, `Socket` to nahi, rail count, phir `all_reduce_perf`.

## Aaj ka rule

2 nodes × 4 GPUs. Andar NVSwitch. Bahar 4 rails. Ek ring do IB hops pe atak kar teen rails khali chhod deta hai. Topology-aware AllReduce pehle node ke andar ReduceScatter karta hai, phir har shard apni rail pe, phir node ke andar AllGather. Chunk node ke andar NVLink pe rehta hai jab tak boundary na aaye.
