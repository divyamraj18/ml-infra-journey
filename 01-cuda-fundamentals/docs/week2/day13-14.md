# Day 13–14: 8 GPUs, 2 nodes, ek AllReduce

Weekend ka kaam yeh diagram hai. 8 GPUs, 2 nodes, iska matlab **4 GPUs per node**. DGX 8-GPU box nahi hai. Do aadhe boxes hain, beech mein fabric hai.

## Physical topology

```text
Node 0                                      Node 1
GPU0   GPU1   GPU2   GPU3                   GPU4   GPU5   GPU6   GPU7
  \     |      |     /                        \     |      |     /
        NVSwitch                                    NVSwitch
   |     |      |     |                        |     |      |     |
  NIC0  NIC1   NIC2  NIC3                     NIC4  NIC5   NIC6  NIC7
   |     |      |     |                        |     |      |     |
 rail0  rail1  rail2  rail3                   rail0  rail1  rail2  rail3
   \     |      |     /                        \     |      |     /
        leaf / spine (InfiniBand ya RoCE)
```

Node ke andar har pair NVSwitch pe hai. Day 8 wala ~900 GB/s, agar yeh H100 hain. Node ke bahar sirf NIC.

**Rail** same index ke NICs ko jodti hai. Node 0 ka GPU0 aur Node 1 ka GPU4 dono rail 0 pe hain. Unke beech ka IB hop spine cross kiye bina ho sakta hai, agar fabric rail-optimized hai.

`nvidia-smi topo -m` node ke andar NV aur PIX dikhayega. Doosre node ka GPU us matrix mein hoga hi nahi. Woh door hai, `NET/IB` se.

## Ek naive ring

Ranks `0-1-2-3-4-5-6-7-0`.

```text
GPU0 -> GPU1 -> GPU2 -> GPU3 -> GPU4 -> GPU5 -> GPU6 -> GPU7 -> GPU0
         NVLink hops          IB hop          NVLink hops         IB hop
```

Sirf do hops inter-node hain: `3 → 4` aur `7 → 0`. Dono ek hi rail use karte hain agar NCCL yeh ring aise hi bichha de. Rail 1, 2, 3 khali. 4 × 400 Gb/s mein se 400 Gb/s kaam kar raha hai. Intra-node hops NVLink pe saste hain. Bottleneck woh do IB hops hain.

Ring AllReduce phir bhi sahi jawab dega. Bus bandwidth ek rail ki hogi, chaar ki nahi.

## Jo NCCL banana chahta hai

Topology dikhti hai to ek ring nahi, **chaar rings**, ek per rail. Har step pe chaaron NICs bytes le jaate hain.

Hierarchical pattern, jo do nodes pe naturally baithta hai:

```text
1. Intra-node, NVLink
   Node 0: GPU0..GPU3  ReduceScatter of the local buffer
   Node 1: GPU4..GPU7  ReduceScatter of the local buffer
   Ab har GPU ke paas buffer ka 1/4 summed-within-node shard hai.

2. Inter-node, ek rail per shard
   GPU0 <-IB rail0-> GPU4     inke shards ka sum
   GPU1 <-IB rail1-> GPU5
   GPU2 <-IB rail2-> GPU6
   GPU3 <-IB rail3-> GPU7
   Chaaron rails ek saath.

3. Intra-node, NVLink
   AllGather, taaki node ka har GPU poora AllReduce result rakh le.
```

Step 2 chhota hai kyunki shard `S/4` hai, aur chaar rails parallel hain. Naive ring mein poora traffic ek IB hop ke through line lagata tha.

Buffer `S = 14 GB` (7B BF16 gradients) ho, to step 2 pe har rail `S/4 = 3.5 GB` ek direction mein dekhta hai, phir result wapas. Exact byte count algorithm pe depend karta hai. Order yeh hai: inter-node bytes `S` ke `1/nodes` ke aas-paas, rails jitni parallel. Intra-node bytes NVLink pe hain, jahan 900 GB/s hai, isliye woh IB se pehle khatam ho jaate hain.

## Ek chunk ko haath se ghumana

8 chunks, `c0…c7`. Sirf `c0` dekho, naive ring pe, ReduceScatter phase.

```text
start:  GPU0 holds c0 (partial from rank 0 only)
step 1: GPU0 sends c0 to GPU1.  GPU1 adds its own c0.
        hop = NVLink
step 2: GPU1 sends c0 to GPU2.  GPU2 adds.
        hop = NVLink
step 3: GPU2 sends c0 to GPU3.  GPU3 adds.
        hop = NVLink
step 4: GPU3 sends c0 to GPU4.  GPU4 adds.
        hop = InfiniBand, rail of NIC3
```

Chaar steps ke baad `c0` abhi poora summed nahi hai. Rank 4, 5, 6, 7 ka hissa abhi jodna baaki hai. Yeh sirf yeh dikhane ke liye hai ki **chunk tab IB pe chadhta hai jab ring node boundary cross karti hai**, usse pehle nahi.

Hierarchical version mein `c0` node 0 ke andar NVLink pe sum hota hai, phir **ek baar** rail 0 pe GPU4 ko jaata hai, jahan node 1 ka already-reduced shard add hota hai. Beech ke GPU1 aur GPU2 us chunk ko IB tak le jaane ke liye relay nahi bante.

## AllReduce ke dauran kaun wait karta hai

Compute tab overlap hota hai jab framework gradient ko buckets mein kaat ke, bucket ready hote hi AllReduce shuru kar de. Poora backward khatam karke ek bada AllReduce karna = GPU network ka intezaar kare. NCCL async hai. CUDA stream pe collective schedule hota hai. Day 4 wali stream yahin kaam aati hai: ek stream pe GEMM, doosri pe NCCL, hardware dono ko overlap kare.

Agar overlap ke baad bhi step time mein `ncclAllReduce` sabse lamba hai, to Day 12: INFO log, `Socket` to nahi, rail count, `all_reduce_perf`.

## Aaj ka rule

2 nodes × 4 GPUs. Andar NVSwitch. Bahar 4 rails. Ek ring do IB hops pe atak ke teen rails khali chhod deta hai. Topology-aware AllReduce pehle node ke andar ReduceScatter karta hai, phir har shard apni rail pe, phir node ke andar AllGather. Chunk node ke andar NVLink pe rehta hai jab tak boundary na aaye.
