# Day 13–14: 8 GPUs, 2 nodes, one AllReduce

The weekend task is this diagram. 8 GPUs across 2 nodes means **4 GPUs per node**. It is not one 8-GPU DGX. It is two half-boxes with a fabric between them.

## Physical topology

```text
Node 0                                      Node 1
GPU0   GPU1   GPU2   GPU3                   GPU4   GPU5   GPU6   GPU7
  \     |      |     /                        \     |      |     /
        NVSwitch                                    NVSwitch
   |     |      |     |                        |     |      |     |
  NIC0  NIC1   NIC2  NIC3                     NIC4  NIC5   NIC6  NIC7
   |     |      |     |                        |     |      |     |
 rail0  rail1  rail2  rail3                   rail0  rail1  rail2  rail3
   \     |      |     /                        \     |      |     /
        leaf / spine (InfiniBand or RoCE)
```

Inside a node, every pair goes through NVSwitch. That is the Day 8 number, about 900 GB/s, if these are H100s. Outside the node, the only path is a NIC.

A **rail** joins NICs with the same index. GPU0 on node 0 and GPU4 on node 1 are both on rail 0. Their InfiniBand hop can avoid the spine if the fabric is rail-optimized.

`nvidia-smi topo -m` shows `NV` and `PIX` inside the node. A GPU on the other node is not in that matrix. It is remote, reached with `NET/IB`.

## One naive ring

Ranks `0-1-2-3-4-5-6-7-0`.

```text
GPU0 -> GPU1 -> GPU2 -> GPU3 -> GPU4 -> GPU5 -> GPU6 -> GPU7 -> GPU0
         NVLink hops          IB hop          NVLink hops         IB hop
```

Only two hops are inter-node: `3 → 4` and `7 → 0`. Both use the same rail if NCCL lays the ring out this way. Rails 1, 2, and 3 sit idle. Out of `4 × 400 Gb/s`, only 400 Gb/s is working. The intra-node hops are cheap because they are NVLink. The bottleneck is those two InfiniBand hops.

The ring AllReduce still returns the right answer. Bus bandwidth is one rail, not four.

## What NCCL wants to build

When it can see the topology, it builds **four rings**, one per rail, not one ring. Every step, all four NICs carry bytes.

The hierarchical pattern that fits two nodes:

```text
1. Intra-node, NVLink
   Node 0: GPU0..GPU3  ReduceScatter the local buffer
   Node 1: GPU4..GPU7  ReduceScatter the local buffer
   Each GPU now holds 1/4 of the buffer, already summed inside its node.

2. Inter-node, one rail per shard
   GPU0 <-IB rail0-> GPU4     sum these shards
   GPU1 <-IB rail1-> GPU5
   GPU2 <-IB rail2-> GPU6
   GPU3 <-IB rail3-> GPU7
   All four rails run at the same time.

3. Intra-node, NVLink
   AllGather, so every GPU in the node holds the full AllReduce result.
```

Step 2 is smaller because the shard is `S/4`, and four rails run in parallel. The naive ring pushed the whole buffer through one InfiniBand hop.

If the buffer is `S = 14 GB` (7B BF16 gradients), each rail in step 2 sees `S/4 = 3.5 GB` in one direction, then the result comes back. The exact byte count depends on the algorithm. The order of magnitude is: inter-node bytes are about `S / number_of_nodes`, spread across the rails. Intra-node bytes ride NVLink at 900 GB/s, so they finish before the InfiniBand hop does.

## Walk one chunk by hand

Eight chunks, `c0…c7`. Follow only `c0` on the naive ring, during the ReduceScatter phase.

```text
start:  GPU0 holds c0 (partial from rank 0 only)
step 1: GPU0 sends c0 to GPU1.  GPU1 adds its own c0.
        hop = NVLink
step 2: GPU1 sends c0 to GPU2.  GPU2 adds.
        hop = NVLink
step 3: GPU2 sends c0 to GPU3.  GPU3 adds.
        hop = NVLink
step 4: GPU3 sends c0 to GPU4.  GPU4 adds.
        hop = InfiniBand, the rail of NIC3
```

After four steps, `c0` is not fully summed yet. Ranks 4, 5, 6, and 7 still have to add their part. The point of the walk is this: **a chunk gets onto InfiniBand only when the ring crosses the node boundary.** Before that it stays on NVLink.

In the hierarchical version, `c0` is summed inside node 0 on NVLink, then crosses **once** on rail 0 to GPU4, where node 1's already-reduced shard is added. GPU1 and GPU2 do not relay that chunk toward InfiniBand.

## Who waits during the AllReduce

Compute overlaps the collective when the framework cuts the gradient into buckets and starts AllReduce as soon as a bucket is ready. Waiting until the whole backward pass finishes, then running one huge AllReduce, means the GPU waits on the network. NCCL is async. The collective is scheduled on a CUDA stream. That is the Day 4 stream idea: GEMM on one stream, NCCL on another, and the hardware overlaps them.

If `ncclAllReduce` is still the longest thing in the step after overlap, go back to Day 12: the INFO log, check it is not `Socket`, check the rail count, then run `all_reduce_perf`.

## Rule for today

2 nodes × 4 GPUs. NVSwitch inside. 4 rails outside. One ring gets stuck on two InfiniBand hops and leaves three rails idle. A topology-aware AllReduce does ReduceScatter inside the node, sends each shard on its own rail, then AllGather inside the node. A chunk stays on NVLink until the ring hits the node boundary.
